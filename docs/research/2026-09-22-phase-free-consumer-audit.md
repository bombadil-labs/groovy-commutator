2026-09-22. Authored by Codex with two independent, read-only Sol audits of
the code and documentation at main
`b0cebf5210288529da865dc990c78ef9618f4be6`. Evidence: repository consumer
audit and scheduling decision, not a mathematical impossibility theorem or a
claim about uses outside this repository.

## Question and decision

Does any current operation in this repository require the affine-oriented
lift's phase-free binary local interface, rather than named tracks, an
ordinary cache, or a simpler self-synchronizing encoding?

**No current downstream consumer does.** The code that genuinely uses
unknown-phase physical windows consists of instruments for constructing,
replaying or analyzing the lift itself. That establishes that the interface
is real, but using those instruments as demand for more lift research would
be circular. The public library and site do not implement or call the lift.
The dimensional application question therefore stays dormant. This is a
stop decision about the current portfolio, not a proof that no useful consumer
can ever exist.

The audit followed the completed [Groovy readout cost
comparison](2026-09-22-groovy-readout-cost.md). That comparison removed the
only presently costed application: a named three-track cache provides the
same original-source Groovy query as the marked six-field jet.

The period-three necklace already supplies the broad phase-free recursive
simulation property more simply. Prior work also covers binary
self-addressing simulation. Therefore the existence of a phase-free binary
interface is not by itself a distinctive application.

## Reopening contract

A future consumer can reopen the question by specifying all of:

1. the exact output or intervention it needs;
2. why the phase is unknown and a named component address is unavailable;
3. the allowed physical geometry, query cadence and workload;
4. initialization, maintenance, storage, decoding and local-access costs;
5. the decision that a positive or negative comparison would change.

At minimum, compare ordinary source access, the named three-track cache when
the target is Groovy, and the period-three necklace when strict phase-free
binary geometry is required. The six-field jet needs a nondominated locality,
readout or intervention tradeoff after all costs are charged. An operation
invented solely to reward its coordinates is not a consumer.

## Contract cautions exposed by the audit

The affine theorem's first-floor radius `(vertical 3, horizontal 2)` gives a
`7 by 5` local stencil: 35 positions in an ambient full-shift local rule. On a
valid period-six beam the first and seventh transverse rows coincide, leaving
30 distinct mutable cells. The former is the completion's table arity; the
latter is the independent on-beam physical key. These numbers must not be
silently interchanged.

Historical uniform-jet scripts use the nonlinear recovery rows
`(X AND D, X AND (1 XOR D))`, while the final affine theorem uses `(0,X)`.
They are locally recodable on valid aligned beams, as the proof state records,
but coordinate-specific decoder or readout statements do not transfer
literally without that recoding. Likewise, a finite-family table completed by
an arbitrary off-domain identity rule is not a universal full-shift
implementation. Finite-ring replay through D4 and the arbitrary finite-depth
theorem are different evidence.

## Limits

This audit establishes the state of the repository at the pinned commit. It
does not search the literature for every possible use, poll unwritten user
needs, optimize an unknown-phase decoder, or prove a lower bound against the
jet. Its consequence is deliberately narrower: the repository currently has
no declared demand that warrants another dimensional experiment.
