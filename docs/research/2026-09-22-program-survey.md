## Is CA/CRDT a new program?

Not yet. It supplied an unusually useful test of the existing question: which
distinctions does a local operation actually need? The fixed-interface Rule-110
compression question is now closed. There is no remaining reason to extend
that enumeration. The result belongs with erased distinctions and local
representation costs, rather than as a fifth independent program.

The connection could justify a separate program if we name a distributed
operation, an established baseline and a measurable improvement. Merely
reproducing asynchronous simulation would not: [Gács](https://cs-web.bu.edu/faculty/gacs/papers/commut.pdf)
already gives commuting asynchronous simulations. [CRDTs](https://arxiv.org/abs/0907.0929)
address replicated objects with concurrent operations. A new proposal must
state which model it uses, including delivery/scheduling assumptions, progress,
readout and stored history. No literal CA-equals-CRDT claim is needed.

## What I recommend actively doing

Keep one umbrella question: **what information must a local computation retain,
and when does changing its representation reduce the cost of a specified task?**
Use the existing Erased Distinctions program as its home and the invariants
work as its method. Limit work in progress to one bounded unit.

The immediate unit should be a comparison design, not another survey of CA.
Its deliverable is a short resource contract with a go/no-go decision. A
concrete first candidate is reading the original Rule-110 Groovy field at one
site from an evolving representation. Compare direct source access, ordinary
stored time slices, the period-three encoding, and the six-field affine lift.
All must return the same original-source quantity; a descendant's native
commutator is a different target and cannot be substituted.

Start on the integer line, with arbitrary binary source configurations and
one synchronous source step as the common cadence. Charge the number of stored
bits per represented source site, physical read neighborhood, local operations
or table size, initialization, and maintaining any stored derived fields.
If a comparison changes physical dimension or allows a packed alphabet, say so:
alphabet labels and spatial cells are not interchangeable free resources.
Finite periodic examples may help check an expression but cannot certify the
whole-line claim. This design is prospective; no advantage is reported here.

Why this candidate? It directly asks whether the project's distinctive extra
coordinates buy something. The target already has a finite local dependency
in the original source, so ordinary direct computation is a strong baseline.
That may close the proposal quickly. Calling a precomputed output a free
coordinate would not establish an improvement. The asynchronous audit gives
the comparison discipline, not an asynchronous implementation of the lift.

Budget the design at one short analysis pass (at most one agent session), using
existing formulas and certificates. No new trajectory generation, all-rule
census, solver campaign or Actions dispatch. Produce one of:

- a concrete, plausibly nondominated resource tradeoff worth a separately
  frozen test or proof;
- an explicit reason the simpler baseline matches or dominates the proposed
  advantage under the chosen costs;
- an unresolved comparison with the missing assumption named, then stop.

If the candidate fails, do not automatically replace the target or invent a
sequence of ever-friendlier benchmarks. Record the answer. Keep the lift as a
completed construction and wait for a real use case. This is a recommendation
for the next design unit, not a claim that a publishable novelty is available.

## The other promising direction, held in reserve

The global-versus-local distinction in the Nakamura result suggests a reusable
certificate interface: given an observation and permitted local access, return
either a correct local transition rule or two reachable inputs that look the
same locally but require different outputs. The synchronous factor examples
and asynchronous audit would supply regression cases.

This could make future representation proposals cheap to reject and useful
outside this particular construction. But building a generic package before
we have a second concrete consumer risks replacing a research treadmill with
an infrastructure treadmill. Promote it only when the next comparison actually
needs it. Any successful finite-domain check must remain labeled finite unless
its domain or reachability is certified complete.

## What would justify reopening the paused work?

A Class-IV continuation needs a behavior defined without choosing it to
recover 54/110, a genuinely external test domain, and a decision its performance
would affect. A defect-mechanism continuation needs a specific prediction or
control task; repair the timing path before relying on the invalidated scores.
A recoder continuation needs a structural insight or demonstrated method gain
on a bounded benchmark. Arithmetic work needs a mechanism with a held-out
prediction beyond the existing correlations.

Curiosity does not have to pretend to be an experiment. Keep a small sandbox
for images, intuitions and examples if that is enjoyable, label it exploratory,
and give it no automatic continuation or promotion to a research claim. The
budget discipline protects the play from becoming an obligation to feed four
programs forever.
