# Protocol: derivative-completed dimensional lift

Date: 2026-09-09
Status: preregistered before class-label evaluation

## Motivation

The unrestricted ECA rule-as-geometry construction places eight truth-table bits on the eight cells surrounding the center of a 3x3 Moore patch. The center is structurally distinguished. The user proposed filling that distinguished site with the incoming discrete derivative that gave rise to the current lower-dimensional center value.

For binary dynamics define the incoming derivative at site x and time t as

\[
\delta_t(x)=S_{t-1}(x)\oplus S_t(x).
\]

This protocol asks whether that apparently small completion exposes a dimension-uniform rule/state/change architecture.

No Wolfram class labels may be used to choose spatialization, role ordering, native rule family, or success criterion in this protocol.

## First exact counting observation

A binary center-independent totalistic radius-one Moore rule in dimension d depends only on the number of live cells among its `3^d-1` outer neighbors. The count ranges from `0` through `3^d-1`, so its rule table contains exactly

\[
M_d=3^d
\]

bits.

A side-three d-dimensional torus also contains exactly `M_d` cells. Thus in this declared native family, a rule table, a minimal side-three state, and its derivative field all have the same bit capacity.

A radius-one neighborhood in dimension `d+1` contains

\[
M_{d+1}=3M_d
\]

cells, i.e. three transverse d-dimensional slices. Therefore for `d>=2` the three equal-sized objects

\[
(\text{rule},\text{state},\text{incoming derivative})
\]

fit exactly into one complete `(d+1)`-dimensional radius-one neighborhood with no padding.

This is a storage identity only. It does not yet prove a commuting dynamical lift.

## Base bootstrap from ECA to 2D

An unrestricted ECA has eight output bits. A 3x3 Moore patch has nine cells. For a frozen shell spatialization `sigma`, define the completed 3x3 object by placing the eight ECA rule bits on the shell and one incoming derivative bit at the center.

The resulting nine-bit object is interpreted as the truth table of a 2D center-independent totalistic Moore rule, whose table has one bit for each neighbor count `0..8`.

This base operation is context-dependent because the center derivative is a trajectory value. It therefore defines initially

\[
\Lambda_1^\sigma(R_1,\delta)\in\mathcal T_2
\]

rather than a static map `R_1 -> R_2`.

The protocol must report separately whether any later compatibility condition removes this context dependence or whether the correct dimensional object is inherently dynamic.

## Recursive candidate for d >= 2

Let `T_d` be the center-independent totalistic family above. Let

- `r in {0,1}^{M_d}` be a native d-dimensional rule table,
- `s in {0,1}^{M_d}` be a local side-three d-dimensional state block or explicitly declared minimal torus state,
- `delta in {0,1}^{M_d}` be its incoming derivative field.

Use balanced-ternary coordinate order to identify indices `0..M_d-1` with the d-dimensional side-three coordinates. Add one transverse ternary digit in dimension `d+1`.

For a frozen role ordering `pi` of `(rule,state,derivative)`, define

\[
\Lambda_d^\pi(r,s,\delta)
\]

by placing those three `M_d`-bit blocks on the three transverse slices and reading the resulting `3M_d=M_{d+1}` bits as the truth table of a native rule in `T_{d+1}`.

The canonical primary ordering is transverse `(-1,0,+1) = (rule,state,derivative)`. The other five role permutations are retained as declared controls and are not selected according to rule identity.

## Distinguish type closure from dynamical closure

The counting identity makes native *type* closure automatic for the recursive candidate. That alone cannot discriminate any dynamical class.

The nontrivial research target is an exact dynamical compatibility condition. Candidate conditions must be frozen before class labels are attached. The first conditions to investigate are:

1. **Derivative consistency.** The derivative block supplied to the lift equals the derivative generated by the declared lower-dimensional evolution.
2. **Lift/evolve commutation.** Lifting the lower rule/state/change triple and then applying the declared higher-dimensional native evolution agrees with first evolving the lower triple and then lifting it.
3. **Recursive context closure.** The data required for the next lift is recoverable from the lifted native object and its own evolution, without an external lower-dimensional history channel.
4. **Rule-only specialization.** Determine whether the dynamic lift factors through a static rule map on any nontrivial subset, or whether trajectory context is essential.

A class claim requires one of these dynamical conditions, not the storage identity.

## Self-substrate control

Because `T_d` rule tables and side-three d-torus states have equal size, a tempting specialization sets the state equal to the rule table itself. This control is to be analyzed explicitly, not assumed interesting.

If this specialization collapses to trivial population-dependent dynamics, record that as an obstruction and do not use it as a class discriminator.

## Spatialization family at the ECA bootstrap

For the base ECA shell placement, retain the same anti-overfitting discipline as the main dimensional-closure protocol.

Primary minimal family:

- consecutive perimeter orderings, yielding 16 labeled placements and two square-symmetry-inequivalent cases (first bit on corner vs edge-center);
- both clockwise and counterclockwise conventions included through symmetry accounting.

Secondary exhaustive family:

- all `8!` shell assignments, reduced by the `D4` action with multiplicities retained;
- no favorable assignment may be selected post hoc.

The derivative occupies the geometric center in every base spatialization.

## Immediate questions

Before any Wolfram labels are joined, determine:

- whether the completed 8+1 base object has a natural symmetry-respecting count-index decoding;
- whether the `(rule,state,derivative)` three-slice recursion yields a well-defined local evolution without hidden context;
- whether the incoming derivative supplies exactly the context needed for recursive closure or merely increases storage;
- whether any exact commutation relation survives from 2D to 3D under one frozen recipe;
- whether the self-substrate control collapses analytically.

## Decision rule

If the derivative-completed construction only establishes a universal storage bijection, it is architectural and supplies no evidence for Class IV.

If one fixed dynamical compatibility test is nontrivial, compute it for the complete frozen rule/spatialization family before attaching class labels.

If context is irreducibly required, retain the result as evidence that the natural dimensional object is a rule/state/change process rather than a static rule ladder; do not silently rewrite it as `R_d -> R_{d+1}`.
