# Cohabitation compares constraints, not chosen completions

For a fixed common local neighborhood, partial Boolean rules cohabit exactly when their shared forced entries agree. An unspecified entry imposes no requirement; a forced zero does. Pairwise compatible partial assignments have a common completion for the whole collection, provided there are no additional restrictions on completions.

If P and Q are compatible, requiring a completion of P to host Q adds |K_Q minus K_P| independent table commitments. If they conflict, no common completion exists. The smallest Hamming separation between their completion families equals the number of conflicting forced entries. This minimum set separation is not generally a metric: unspecified rules can have zero separation from mutually incompatible rules.

In the current six-field D2 cache, pooled complete source rings seven and eight yield 20,944 compatible pairs among 32,640. Of these, 14,743 have shared pinned support and 6,201 have none. Individually completing both rules under any of four fixed default policies gives distinct full tables for every pair, so completed-table equality loses all the genuine edges. This does not establish that the unavailable historical cohabitation code used that incorrect substitute.

Raw partner counts still fail to single out 54/110; rule 0 leads. The counts depend on the declared neighborhood and source families. They are exact finite constraint counts, not an infinite-input theorem or a Class-IV discriminator. The independent response-quotient failure is unchanged.
